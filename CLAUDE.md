# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
bun install
bun run start [path] [-t theme]   # run the TUI (bun src/cli.tsx); needs a real TTY
bun run dev                       # run against ./examples
bun test                          # all tests (bun:test, tests/*.test.ts[x])
bun test tests/markdown-fixes.test.ts -t "tables"   # single file / test by name
bun run typecheck                 # bunx tsc --noEmit (covers src, scripts, tests)
bun run build                     # compile single binary ./brothy (tree-sitter parsers are embedded); delete it after checking
bun run snapshot examples --size 100x30 --keys "tab j s"   # headless frame dump
bun run screenshots               # docs/*.{svg,png} (needs resvg); helpers in scripts/session.tsx, scripts/pipeline.ts
bun run demo [-- short|full]      # docs/demo.gif + demo-short.mp4 / demo.mp4: real-time session, then a CSS 3D compositor (scripts/cinema.ts, scripts/stage.html) in headless Chromium via Playwright (fetched on first run); needs resvg, ffmpeg; ~8 min
```

There is no linter. `scripts/snapshot.tsx` renders `<App>` via OpenTUI's `testRender` and prints the frame; keys are space-separated (`tab`, `enter`, `esc`, `up`/`down`, `type:<text>`, `wait:<ms>`, `C-<key>` for ctrl, or any single key). Also takes `--theme`, `--json out.json` (colored spans) and `--config <dir>`; by default config (theme, sidebar) lives in a throwaway temp dir, so snapshots never read or write `~/.config/brothy`. It waits for code-block highlighting to land before capturing and calls `shutdownHighlighter()` at the end. Use it to check UI changes, since the TUI can't be driven interactively.

## Architecture

Bun + React 19 + OpenTUI (`@opentui/core`/`@opentui/react`, custom JSX import source set in tsconfig). Terminal Markdown reader.

- `src/cli.tsx` — entry: `parseArgs`, stat the path, TTY check, create the renderer, mount `<App>`. Every failure prints `brothy: <msg>` and exits 1. Theme precedence: `--theme` flag, then the config file.
- `src/args.ts` — pure `parseArgs(argv)` returning `Args | { error }` (validates theme names against `themes`; at most one path).
- `src/config.ts` — `~/.config/brothy/config.json` (`configPath()` resolves lazily and ignores a relative `XDG_CONFIG_HOME`). Holds `theme`, `sidebar` (`{ view, hidden }`; replaces the old `folds`, which are migrated once and dropped on the next save), `wide` (full-width toggle, key `w`), `transparent` (key `T`, `--transparent` wins per run) and the `zen` settings; `loadConfig` validates, `saveConfig` merges and refuses to overwrite a file that doesn't parse.
- `src/App.tsx` — the entire UI and all state/keybindings. Layout: status rows (top line — a running head: `LOGO` (Nerd Font bowl, U+F0617) at column 0, folder over the panel, `Title › section` and the state cluster aligned to the text column, built by `headerLayout` — plus a faint rule on the gap row; ghost line with fading hints and toasts, progress line — shared with zen), one tabbed panel (Files / Outline / Info, `1 2 3`; a drawer with a scrim below 100 columns), borderless document at an 80-column measure (`s` swaps in Source); `T` swaps the `surface()` fills (theme.ts) for `"transparent"` on the root, status rows and inline panel; popups, scrim, drawer and code fill stay painted (a clear drawer would show the text under it); one `KEYMAP` table drives dispatch, help and footer hints. A `hl` counter in the UI store is bumped when code highlighting lands so the memoized document re-renders. Zen (`z`, settings popup `Z`) is a separate root keyed "zen"; it is runtime-only, and its settings persist under `zen`. `f` enters the `label` mode (`ui.labels`; not "hint", which is the footer key hints); labels drop when the view or scroll moves, and a missing heading leaves the note at its remembered position. The `f links` footer hint is `spare` (`fitHints` drops it first). Links resolve against `ui.linkTree`: the enclosing vault (`findVault`, nearest `.obsidian/`) when a single note was opened inside one, else the Files `tree`. `C-p` opens the switcher (`ui.switcher`, mode `switch`) over `ui.linkTree`. `o` opens the Open picker (`ui.opener`, mode `open`); `ui.root` is the workspace, and every rebuild (start, `o`) goes through `workspace(root, note?)` — `switchWorkspace` also records the project, drops the vault index, re-arms the watcher and clears history. The index lives in the `vault` ref and is built on first use; `r` drops it. Recents are the notes the document had focus with.
- `src/overlay.tsx` — popup/picker components (theme picker, find list, help).
- `src/panel.ts` — pure data for the panel: Outline and Info rows, links. `noteIndex` (cached per tree), `resolveLink`, `linkDest` and `findHeading`/`headingKey` decide where a link goes.
- `src/status.ts` — status strings (`LOGO`; `WORDMARK`/`fitWordmark` — the "brothy" wordmark in the empty state, help popup, README and `--version`; top line: `headerLayout`, `shrinkFolder`, `logoState`, `mainHeadingVisible`, `locationParts`; state cluster, progress label, hint fitting) and toasts.
- `src/nav.ts` — pure helpers for scrolling, search, scrollbar thumb and strip layout, match index and the `cached` single-entry memo (unit-tested without a renderer). Also link labels (`visibleLinks`, `linkLabels`, `narrowLabels`, `overlayAt`) for the `f` mode, drawn over rows at render time.
- `src/zen.ts` — Zen mode's pure side: `ZenConfig` (`measure` is a number or `"full"`; `stepMeasure` is the dial) + `normalizeZen`/`pickZen` (field-wise validation used by `config.ts`), settings-popup rows (`zenRows`, `zenAdjust`), `sectionRanges`/`sectionAt`, `typewriterTop`, `pageSlice`, `headingPath`, `dimSpans` (Spotlight), `wordSuffix`/`minutesLeft`, `prompterRate`, `fadeStep(elapsed, hold)` with `HINT_HOLD` (hint/ghost fade).
- `src/vault.ts` — the `C-p` switcher's pure side: the lazy index (`NoteDoc` per note: aliases, Source-outline headings, searchable text — heading lines blank, inline marks stripped by `plainLine`, so text hits never repeat Headings and context matches its highlights — with `foldSame` offsets; `refreshIndex` re-reads changed mtimes in `CHUNK`s and stops when `live()` is false) and the search (`searchVault`: Notes / Headings / Text with `SWITCH_CAP`; `recentSection`; row helpers `switchRows`/`stepRow`/`nextSection`). A heading hit's index is `view.headings[i]` by outline parity.
- `src/projects.ts` — recent projects (`projects.json` next to `config.json`, `ProjectEntry`: root, lastNote, Preview top, at; cap 20) and the `o` picker's pure side: `remember`, `rankProjects`, `pathCompletions` (injectable `DirIO`), `openRows`, `tildify`/`expandTilde`.
- `src/history.ts` — `H`/`L` back/forward, pure: `visit` (cuts forward, no consecutive duplicates, cap 100; a `peek` entry — a Files preview — is replaced by the next visit until `keep` marks it focused or followed from), `stepTo`/`go`/`drop`. App holds it in `ui.history`; every open goes through `openFile(path, how)`, and an entry stores the scroll entry (`Spot`: key, top, geo) the note was left at.
- `src/watch.ts` — `watchPath`: live reload that survives atomic saves (watches the parent dir) and falls back to polling with a synchronous baseline.
- `src/markdown.ts` — core design: `marked` lexer output is converted to **pre-wrapped, styled lines** (`Span[]` per `Line`) at a given width. Scrolling, heading jumps (`Rendered.headings` holds line numbers), and search all operate on exact line indexes, so any change to rendering must keep that line↔heading mapping consistent. Also holds `wrap` (grapheme-aware, `preserve` mode for code), `parseFrontMatter`, `stats`, and `renderSource` (its outline mirrors the preview's headings; `Rendered.srcRow` maps each source line to its first row). `sourceScan` gives the Source outline (with source lines) and the searchable lines without laying out (the switcher's index). Input is normalised first (BOM, CRLF, control characters). Tables never exceed the width: columns shrink, narrow ones truncate with `…`, columns that cannot fit become a final `…` column. Widths use `Bun.stringWidth`. Obsidian: one shared `Marked` instance (`md`, with `lexBlocks`/`lexInline`) carries the `==highlight==` extension — never lex with `new Lexer` or `Lexer.lexInline`. `%%comments%%` are cut before lexing (`stripComments`); `scanComments` gives Source the same hidden lines so both outlines stay equal. Callouts (`CALLOUT_KINDS`, `calloutOf`) render through `blocks()` so body headings keep their lines; `dataview`/`dataviewjs`/`tasks` fences are one row; HTML goes through the `HTML_TAGS` whitelist (`stripTags`). Wikilinks are a second extension on `md` (`wikilinkExt`, `parseWikilink`, `wikiLabel`); every link token gets an id that rides on its spans as `Span.link` into `Rendered.links` (`same()` compares it so links never merge). `render(…, { exists })` mutes unresolved targets.
- `src/highlight.ts` — code-block colors. JS/TS/JSX/TSX/Zig go through OpenTUI's tree-sitter worker (async); everything else uses a small per-language-family fallback (comments/strings/numbers). `render()` only reads the cache (`codeSpans`) and records misses in `Rendered.pending`; callers `await ensureHighlights(pendingHighlights(r))` and re-render. The cache stores semantic kinds, colored from the `Theme` at render time. A highlighted block must have exactly as many lines as a plain one. The parser worker keeps the process alive: call `shutdownHighlighter()` in scripts/tests (the app exits via `process.exit`).
- `src/spans.ts` — `Span` and the attribute flags `A` (re-exported by `markdown.ts`; exists to avoid an import cycle with `highlight.ts`), plus `safe`/`safeLine`: control characters (C0, DEL, C1) become U+FFFD so nothing reaches the terminal as an escape sequence. Applied at the sources (`normalize`, front-matter values, `FileNode.name`/`rel` — `path` stays raw for I/O — and decoded link targets) and again in `flash()` and the `Row`/`Line` span renderers. `safeLine` also turns tab/newline into spaces for one-row text.
- `src/files.ts` — recursive markdown scan (`scanTree`: depth-limited, symlink-safe via realpath, skips `node_modules` and dot-dirs except `.github`, stops after `SCAN_LIMIT` entries and sets `root.truncated`; a symlink whose target leaves the root is followed but flagged `outside`, shown as a muted ↗ in Files), `visibleRows`, `ancestorsOf`, `folderCounts`, `fuzzyHits` (by code point), `scoreName` (shared name scoring), `rankNotes` (optional `aliases`, ranked between name and path), `stem` and `findVault`.
- `src/theme.ts` — 26 palettes (13 families: a dark theme plus a `-light` twin; `Theme.mode`; darks listed first, which is the picker's order — `one` is `one-dark`/`one-light`). Every color used in rendering comes from a `Theme` passed down. Palettes are literal, already tuned (opencode, MIT, plus Noodle's shape for the brothy themes; `brothy-light` is original): `tests/theme.test.ts` enforces 4.5:1 for text/muted/primary/secondary/accent and 3:1 for error/warning/success/info on `background` and `backgroundPanel`, and content colors on `backgroundElement` (code-block fill; text 4.5, rest 3). Theme choice is always explicit (no terminal auto-detect). Adding a theme means passing those tests; `contrast()` is exported for that.

## Gotchas

- OpenTUI's React reconciler does not clear style props that disappear between renders. Conditional branches rendering different boxes in the same spot need distinct `key`s (see the `key="empty"`/`"error"`/`"lines"` and `"side-inline"`/`"side-drawer"` boxes in `App.tsx`).
- `marked` 18 gives raw text for code spans and pre-decoded numeric entities in text; `markdown.ts` decodes only named entities (single pass). marked's lexer also hangs on tables with ~150k+ rows.
- OpenTUI's tree-sitter worker ignores `#match?` predicates, so every identifier arrives as variable+type+constant; `tokenize` in `highlight.ts` re-checks `type`/`constant` against the text. `preloadParser` is unreliable for aliases; use the static `PARSER_FILETYPES` list (a test checks it against the library).
- Zen keeps the per-file scroll `top` as the only position: in Typewriter it *is* the reading line, in Pages it is the page anchor (its section is the page), and in both `maxTop` is the last line. Display goes through `derive().win` (`first`, `lo`, `hi`) — never slice `view.lines` from `top` directly in zen.
- Outline parity: anything Preview hides (comments, collapsed fences) must also be skipped by `sourceStructure`; `tests/markdown-obsidian.test.ts` checks `render` vs `renderSource` outlines.
- Tests: `markdown*`, `files`, `config`, `args`, `nav`, `panel`, `status`, `watch`, `theme`, `highlight`, `zen`, `vault`, `history` and `projects` are unit tests; `overlay.test.tsx` mounts the popup components through `testRender`; `cli.test.ts` spawns the CLI (non-TTY paths); `app.test.tsx` mounts `<App>` through `testRender` with `XDG_CONFIG_HOME` pointed at a temp dir (sidebar and theme persist, so the config is cleared after each test) and shuts the highlighter worker down at the end. UI changes are also worth a look through the snapshot script.
