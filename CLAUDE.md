# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
bun install
bun run start [path] [-t theme]   # run the TUI (bun src/cli.tsx); needs a real TTY
bun run dev                       # run against ./examples
bun test                          # all tests (bun:test, tests/**/*.test.ts[x])
bun test tests/markdown/markdown-fixes.test.ts -t "tables"   # single file / test by name
bun run typecheck                 # bunx tsc --noEmit (covers src, scripts, tests)
bun run lint                      # biome check . (format + recommended lint rules; biome.jsonc says why each deviation is off); `bun run format` rewrites
bun run knip                      # unused files, exports and dependencies (knip.jsonc; tests and scripts count as entries)
bun run fallow                    # fallow 3.37.0: dead code, clones, complexity (.fallowrc.jsonc says why each ignore is there)
bun run fallow:gate               # CI's fallow gate: the whole tree vs .github/fallow-health-baseline.json (the accepted complexity findings, per function), so a new finding or a stale entry fails; a PR also runs `fallow audit --base origin/<base> --worsened error` (an accepted function that grows fails). Refresh only on purpose: after a fix, `bun run fallow baselines prune --health-baseline .github/fallow-health-baseline.json`; to accept a finding, `bun run fallow health --save-baseline .github/fallow-health-baseline.json --baseline-mode identity --report-only` and say why in the commit
bun run build                     # compile single binary ./brothy (tree-sitter parsers are embedded); delete it after checking
bun run snapshot examples --size 100x30 --keys "tab j s"   # headless frame dump
# media tooling (docs screenshots, site casts, demo videos) lives in the private brothy-studio repo: it imports `scripts/session.tsx` (keep its exports: `mount`, `press`, `frame`, `frameKey`, `settle`, `sleep`, `Frame`) and `src/*` from a checkout of this repo and writes docs/*.{svg,png,mp4,gif} and site/public/casts/*.cast into it; they are committed here by hand, with the brothy commit they were rendered from in the message
cd site && bun install && bun run dev|build   # docs site (Astro Starlight; deployed by pages.yml; screenshots via the src/assets/docs symlink to ../docs); root typecheck/test ignore it
bun scripts/contrast.ts [theme…]  # WCAG table of each role on page / panel / code fill + the closest accent pair (default brothy brothy-light; ✗ = below the house floors tests/theme/theme.test.ts enforces for them)
bun scripts/site-art.ts           # site/src/art.json: the site's wordmark, welcome bowl and steam frames as SVG data from WORDMARK / welcomeArt / steamRows (committed: the site build has no root deps; tests/site/site-art.test.ts fails when stale)
```

Biome is the formatter and linter (CI runs `biome ci .` and `knip`; `git config blame.ignoreRevsFile .git-blame-ignore-revs` hides the formatting commit from blame). `scripts/snapshot.tsx` renders `<App>` via OpenTUI's `testRender` and prints the frame; keys are space-separated (`tab`, `enter`, `esc`, `up`/`down`, `type:<text>` — `\s` types a space, so single-quote `--keys` — `wait:<ms>`, `C-<key>` for ctrl, or any single key). Also takes `--theme`, `--json out.json` (colored spans) and `--config <dir>`; by default config (theme, sidebar) lives in a throwaway temp dir, so snapshots never read or write `~/.config/brothy`. It runs with `motion` off (welcome drawn still and inked), waits for code-block highlighting to land before capturing (`settle`: the frame unchanged for 600 ms, at most 5 s) and calls `shutdownHighlighter()` at the end. Use it to check UI changes, since the TUI can't be driven interactively.

## Architecture

Bun + React 19 + OpenTUI (`@opentui/core`/`@opentui/react`, custom JSX import source set in tsconfig). Terminal Markdown reader.

`src/` is split by domain. `tests/deps.test.ts` enforces the direction: `lib/` imports nothing outside `lib/`; `markdown/`, `ai/`, `notes/`, `ui/`, `theme/` and `system/` never import `app/` or `App.tsx`; no module loads itself through its runtime imports (type-only imports aside). The folders still import each other otherwise (e.g. `theme/themepick` renders through `markdown/render`, which reads `theme/theme`). `tests/` mirrors the folders.

### src/ (root)

- `cli.tsx` — entry: `parseArgs`; `--help` (family names wrapped under `HELP_INDENT`, a single-mode family marked `(<mode> only)`) and `--version` (`WORDMARK` + `VERSION`); stat the path (ENOENT → `no such file or directory: <path>`, a folder is read to surface EACCES, a non-Markdown file warns and opens); TTY check; `createCliRenderer`; mount `<App>`. Stdin mode (`-`, or a pipe with no path): `Bun.stdin` through `readCapped` (`input too large (limit 5 MB)`, blank → `nothing on stdin`), `/dev/tty` opened as a `tty.ReadStream` and handed to the renderer as `stdin` for keys, the TTY check is then stdout + `/dev/tty`; `root` is the cwd and `<App stdin={text}>` gets the text. Every failure prints `brothy: <msg>` and exits 1. Theme: `--theme`, else config `theme`; either may be a family name (`resolveTheme`).
- `App.tsx` — the root: `VERSION`, `AppProps` (`root`, `initialFile`, `themeName`, `transparent`, `fetch`, `edit`, `stdin`, `linkScanDelay`, `motion`). Holds the store (`initUI` once; `set` merges and bumps) and the refs; every render builds `makeDerive` → `makeCtx(…)` → the feature factories → `makeActions`, then `useAppEffects` and `useKeyboard(onKey)`. Panel and document are built before the too-small return because they write list tops back. Below `MIN_W`×`MIN_H` it draws `tooSmall`; else one of two roots keyed `"zen"` / `"main"` (`onMouse={pointer.note}`, `surface(t, transparent).main`). Builds `FooterState` for `footerHints`; its own effects poke hints on a context change, run `glossEntered` on `glossAt` (section changes only) and fetch the theme sample's highlights (`hlSample`).

### src/app/ — App's impure pieces

`store.ts` holds the one store; `ctx.ts` builds the `AppCtx` each render (`makeCtx`); feature factories `makeX(ctx, deps)` close over it and read `ui.current` at call time (a big one spreads smaller factories, one per concern, and keeps its return shape); draw functions `xBox` / `xOverlay(ctx, d, …)` take the context and this render's `derive()`. `keymap.ts` and `input.ts` are pure.

Constants `OPEN_DELAY`, `ZEN_DIM`, `SCRIM_DIM`, `MAX_DEPTH`, `WHEEL_ROWS`, `MIN_W` 60, `MIN_H` 14; types `Focus`, `Prompt`, `FileRow`, `Spot`, `Baseline`, `DeltaState`; the `jobs` ref's `Job` and `jobKey(kind, id)` (`tldr:<path>`, `gloss:<sectionId>`, `delta:<path>`, bare `ask`).

### src/markdown/ — Markdown in, styled terminal lines out

The one lexer, the Preview and Source renderers, front matter, stats, code highlighting and source-line sections. Pure apart from the tree-sitter worker.

- `lexer.ts` — the one shared `Marked` instance `md` (private): every lex goes through `lexBlocks`, `lexOutline` or `lexInline` — never `new Lexer` or `Lexer.lexInline`. It carries the Obsidian extensions `==highlight==` and wikilinks (`wikilinkExt`, `parseWikilink`, `wikiLabel`, `isWikilink`); `CappedLexer` caps an inline run at `INLINE_CAP`. `normalize` (BOM, CRLF, `safe`); `tokenOf` narrows a token after its `type` check. `%%comments%%`: `stripComments` gives Preview's input, `scanComments` gives Source and the outline the same hidden lines.
- `frontmatter.ts` — `parseFrontMatter(src)` → `{ entries, body, offset }` (values through `safeLine`; Preview renders `body`); `parseProperties` (the YAML Obsidian writes: scalars, flow and block lists, comma lists for tags/aliases; Info props and the vault's aliases).
- `render.ts` — core design: Preview converts the lexer's tokens into **pre-wrapped, styled lines** (`Span[]` per `Line`) at a given width (`render(src, max, t, { headings, exists })`). Scrolling, heading jumps (`Rendered.headings` holds line numbers) and search all operate on exact line indexes, so any rendering change must keep the line↔heading mapping. `Heading.last` (Preview only; Source leaves it undefined, so read `last ?? line`) is the heading's last text row, where the AI marks go. `Geometry` (heading lines and total, what scroll offsets are measured against). `Rendered` also has `plain` (search), `pending` (code not yet highlighted) and `links`: every link token gets an id that rides on its spans as `Span.link` (`sameStyle` compares it, so links never merge); `exists` mutes unresolved targets. Tables never exceed the width (`fitWidths`: columns shrink, narrow ones truncate with `…`, columns that cannot fit become a final `…` column). Callouts (`CALLOUT_KINDS`, `calloutKind`, `calloutOf`) render through `blocks()` so body headings keep their lines; `dataview`/`dataviewjs`/`tasks` fences are one row; HTML goes through the `HTML_TAGS` whitelist (`stripTags`); `decode` handles entities. The heading styles (Source ignores them) are drawn here. Exports `inline`, `plainOf`, `pad` for `source.ts`.
- `heading-style.ts` — `HEADING_STYLES` (`classic`, `bars`, `ladder`, `rules`: the order `#` cycles) and `HeadingStyle`; a leaf, so `system/config.ts` validates `headings` without loading the renderer.
- `source.ts` — the Source view and the outline off source lines: `sourceStructureLexed` (the same lexer's tokens) or, when `needsLexer` finds nothing it can't follow, the faster line-based `sourceStructureLines`. `sourceScan(src, t?)` gives the outline (with source lines) and the searchable lines without laying out (the switcher's index, sections, `e`). `renderSource` draws raw Markdown with a gutter; its outline mirrors Preview's headings (outline parity); `Rendered.srcRow` maps each source line to its first row.
- `stats.ts` — `stats` (Info, by lexing), `wordStats` (words and minutes without lexing), `stripCode`.
- `highlight.ts` — code-block colors. JS/TS/JSX/TSX/Zig go through OpenTUI's tree-sitter worker (async); everything else uses a small per-language-family fallback (comments/strings/numbers). `render()` only reads the cache (`codeSpans`) and records misses in `Rendered.pending`; callers `await ensureHighlights(pendingHighlights(r))` and re-render. The cache stores semantic kinds, colored from the `Theme` at render time (`kindStyle`). A highlighted block must have exactly as many lines as a plain one. The worker keeps the process alive: call `shutdownHighlighter()` in scripts/tests (the app exits via `process.exit`).
- `sections.ts` — pure, over `sourceScan`: `noteSections` (per heading: depth, `key`, `ord` among equal keys, `own`/`tree` source-line ranges, one pass with a depth stack; index -1 is the lead-in), `sectionSource(src, i, "own" | "tree", secs?)` (front matter, comments and the heading removed; pass `secs` to skip re-scanning), `sectionOf(headings, line)` (derive's `currentHeading` rule), `sectionId(path, s)` = `path#key#ord` (stable across edits elsewhere), `headingKey`. By outline parity `index` is the same heading in Preview, Source and the vault index.

### src/lib/ — leaf helpers

Imports nothing in src outside `lib/`.

- `spans.ts` — `Span` and the attribute flags `A`; `safe`/`safeLine`: C0 (but tab and newline), DEL, C1, bidi controls, ZWSP/LRM/RLM, BOM and stray ZWJ/ZWNJ become U+FFFD, so nothing reaches the terminal as an escape sequence or reorders text. Applied at the sources (`normalize`, front-matter values, `FileNode.name`/`rel` — `path` stays raw for I/O — decoded link targets) and again in `flash()` and the `Row`/`Line` span renderers. `safeLine` also turns tab/newline into spaces for one-row text. `lineText`.
- `text.ts` — `width` (`Bun.stringWidth`), `segmenter`/`graphemes`, `spanWidth`, `sameStyle`/`pushSpan`/`mergeSpans`, `truncate`/`truncateLeft` (per grapheme, add `…`), `wrap(spans, max, first, rest, preserve)` (grapheme-aware word wrap; `preserve` for code), `fmtNum`, `plural`, `clamp`, `superscript` (tab key numbers).
- `json.ts` — `isRecord`, `readJSON` (never throws; `lenient` drops a BOM, a blank file is `{}`), `configHome`/`cacheHome` (resolved per call, a relative XDG path ignored), `writeFileAtomic(file, text, newMode?)` (temp file + rename; a new file gets `newMode`, an existing one keeps its mode).

### src/theme/ — palettes and the `t` picker

- `theme.ts` — **no imports**: `site/src/themes.ts` loads it with only `site/` deps, and `.github/workflows/pages.yml` triggers on its path. 42 palettes (22 families: 20 a dark theme plus a `-light` twin, synthwave84 and vesper dark-only; `Theme.mode`; darks listed first, which is the picker's order, new families after flexoki alphabetically — `one` is `one-dark`/`one-light`). Every color used in rendering comes from a `Theme` passed down. Palettes are literal, already tuned (opencode, MIT; ayu, nightfox/dayfox, Night Owl/Light Owl, iceberg, oxocarbon, cyberdream, melange, synthwave84 and vesper from upstream, MIT, credited in NOTICE and the file header; the brothy themes are the original Hōjicha palette in Noodle's shape): `tests/theme/theme.test.ts` enforces 4.5:1 for text/muted/primary/secondary/accent and 3:1 for error/warning/success/info on `background` and `backgroundPanel`, and content colors on `backgroundElement` (code-block fill; text 4.5, rest 3). Theme choice is always explicit (no terminal auto-detect). The brothy pair is held to the stricter `HOUSE` floors of `scripts/contrast.ts` (text 7 on page, side and code fill and 13.5 on the page, every other content role 4.5 on all three, borders 1.5, closest accent pair ΔE ≥ 5). Adding a theme means passing those tests; `contrast()` is exported for that. ## Gotchas

- OpenTUI's React reconciler does not clear style props that disappear between renders. Conditional branches rendering different boxes in the same spot need distinct `key`s (see the `key="error"`/`"zen-lines"`/`"lines"` boxes in `app/Document.tsx`, `"side-inline"`/`"side-drawer"` in `app/Panel.tsx`, and `<Welcome key="empty">` in `ui/overlay.tsx`).
- After a render whose hit grid changed, OpenTUI hit-tests the resting pointer again (`recheckHoverState`) and sends `over` to whatever is under it now — a row re-keyed as the highlight moves (`sel`/`row` keys), or scrolled under it — at the last event's cell. A hover handler that acts on every `over` undoes keyboard and wheel moves; guard it with `usePointer().moved` (`ui/overlay.tsx`). A real move sends `out`, then `over`, already at the new cell, so `note` records only the pointer's own events (move, drag, down, up, scroll), from catch-all `onMouse` boxes above the rows; a handler below them that stops propagation calls `note` itself.
- `marked` 18 gives raw text for code spans and pre-decoded numeric entities in text (control characters decoded that way are mapped by `safe`); `decode` in `markdown/render.ts` decodes named entities and any numeric ones left (HTML blocks) in a single pass, refusing control characters. marked's lexer also hangs on tables with ~150k+ rows.
- OpenTUI's tree-sitter worker ignores `#match?` predicates, so every identifier arrives as variable+type+constant; `tokenize` in `markdown/highlight.ts` re-checks `type`/`constant` against the text. `preloadParser` is unreliable for aliases; use the static `PARSER_FILETYPES` list (a test checks it against the library).
- Zen keeps the per-file scroll `top` as the only position: in Typewriter it *is* the reading line, in Pages it is the page anchor (its section is the page), and in both `maxTop` is the last line. Display goes through `derive().win` (`first`, `lo`, `hi`) — never slice `view.lines` from `top` directly in zen.
- Outline parity: Source's headings must be Preview's. `sourceStructureLexed` (`markdown/source.ts`) walks the same lexer tokens, so it agrees by construction; the line-based `sourceStructureLines` mirrors Preview's rules for simple notes only, so anything Preview hides or nests must be mirrored there or sent to the lexer by `needsLexer`. Comment-only lines are skipped through `scanComments().hidden` in both. `tests/markdown/markdown-obsidian.test.ts` checks `render` vs `renderSource` outlines and fuzzes the two paths against each other.
- Tests: `tests/<folder>/<module>.test.ts` mirrors `src/` (`tests/ai/client.test.ts`, `tests/ai/cache.test.ts`; the `markdown*` tests cover the markdown folder together); `tests/cli.test.ts` spawns the CLI (non-TTY paths) and `tests/deps.test.ts` checks the folder rules; `tests/site/` holds `site-art` (`site/src/art.json` is current), `casts` (the committed casts stay within what the site's player replays) and `site-themes`. All are unit tests over pure modules except `tests/ui/overlay.test.tsx` (popup components through `testRender`) and `tests/app/app-*.test.tsx`, which mount `<App>` through `testRender`, black-box: keys in, frame or spans out, AI through a stub `fetch`. Every app test file calls `useAppHarness()` (`tests/app/helpers.tsx`) at its top level: it points `XDG_CONFIG_HOME` and `XDG_CACHE_HOME` at temp dirs, registers the hooks (config cleared after each test, highlighter shut down at the end) and returns `mount`, `keys`, `waitFor`/`waitFrame`, `withEnv`, `withClock`, `aiStub`. Shared helpers in `tests/helpers/` (`tmp`, `env`, `theme` — themes by name, never `themes[0]` — `perf`, `quiet-act`). Nothing in a helper runs at import: bun runs every file in one process, so env or hooks at a helper's top level would leak into the real `~/.config`. UI changes are also worth a look through the snapshot script.
