# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
bun install
bun run start [path] [-t theme]   # run the TUI (bun src/cli.tsx); needs a real TTY
bun run dev                       # run against ./examples
bun test                          # all tests (bun:test, tests/*.test.ts[x])
bun test tests/markdown-fixes.test.ts -t "tables"   # single file / test by name
bun run typecheck                 # bunx tsc --noEmit (covers src, scripts, tests)
bun run build                     # compile single binary ./brothy (tree-sitter parsers are embedded); delete it after checking
bun run snapshot examples --size 100x30 --keys "tab j s"   # headless frame dump
bun run screenshots               # docs/*.{svg,png} (needs resvg, the only converter: rsvg-convert and magick merge words and set ligatures, so a missing resvg fails with install hints); helpers in scripts/session.tsx, scripts/pipeline.ts
bun run demo [-- short|full]      # docs/demo.gif + demo-short.mp4 / demo.mp4: real-time session, then a CSS 3D compositor (scripts/cinema.ts, scripts/stage.html) in headless Chromium via Playwright (fetched on first run); needs resvg, ffmpeg; ~8 min
```

There is no linter. `scripts/snapshot.tsx` renders `<App>` via OpenTUI's `testRender` and prints the frame; keys are space-separated (`tab`, `enter`, `esc`, `up`/`down`, `type:<text>` — `\s` types a space, so single-quote `--keys` — `wait:<ms>`, `C-<key>` for ctrl, or any single key). Also takes `--theme`, `--json out.json` (colored spans) and `--config <dir>`; by default config (theme, sidebar) lives in a throwaway temp dir, so snapshots never read or write `~/.config/brothy`. It runs with `motion` off (welcome drawn still and inked), waits for code-block highlighting to land before capturing (`settle`: the frame unchanged for 600 ms, at most 5 s) and calls `shutdownHighlighter()` at the end. Use it to check UI changes, since the TUI can't be driven interactively.

## Architecture

Bun + React 19 + OpenTUI (`@opentui/core`/`@opentui/react`, custom JSX import source set in tsconfig). Terminal Markdown reader.

- `src/cli.tsx` — entry: `parseArgs`, stat the path, TTY check, create the renderer, mount `<App>`. Stdin mode (`-`, or a pipe with no path): reads `Bun.stdin` through `readCapped` (stops past `MAX_BYTES`: `input too large (limit 5 MB)`), opens `/dev/tty` as a `tty.ReadStream` and hands it to `createCliRenderer({ stdin })` for keys; the TTY check is then stdout + `/dev/tty`; `root` is the cwd and `<App stdin={text}>` gets the text. Every failure prints `brothy: <msg>` and exits 1. Theme precedence: `--theme` flag, then the config file; either name may be a family's (`resolveTheme`: its dark theme, light when that is all it has); a config name nothing resolves toasts `unknown theme "x" in config` once at start and brothy stands in.
- `src/args.ts` — pure `parseArgs(argv)` returning `Args | { error }` (validates `--theme` with `resolveTheme`, so a family name passes and is kept as typed; the error and `--help` list the family names; at most one path; `-` sets `stdin`, `given` says whether a path was typed).
- `src/config.ts` — `~/.config/brothy/config.json` (`configPath()` resolves lazily and ignores a relative `XDG_CONFIG_HOME`). Holds `ai` (opt-in; `normalizeAI`, validated, no keys), `theme`, `sidebar` (`{ view, hidden }`; replaces the old `folds`, which are migrated once and dropped on the next save), `wide` (full-width toggle, key `w`), `transparent` (key `T`, `--transparent` wins per run), `minimap` (key `m`, default on), `headings` (`HeadingStyle`, key `#`; invalid dropped), `motion` (animations: the welcome ink-in and steam; default on) and the `zen` settings; `loadConfig` validates, `saveConfig` merges and refuses to overwrite a file that doesn't parse. `writeFileAtomic(file, text, newMode?)` gives a new file `newMode` and keeps an existing file's mode.
- `src/App.tsx` — the entire UI and all state/keybindings. Layout: status rows (top line — a running head: `LOGO` (Nerd Font bowl, U+F0617) at column 0, folder over the panel, `Title › section` and the state cluster aligned to the text column, built by `headerLayout` — plus a faint rule on the gap row; ghost line with fading hints and toasts, progress line — shared with zen), one tabbed panel (Files / Outline / Info, `1 2 3`; a drawer with a scrim below 100 columns), borderless document at an 80-column measure (`s` swaps in Source); `T` swaps the `surface()` fills (theme.ts) for `"transparent"` on the root, status rows and inline panel; popups, scrim, drawer and code fill stay painted (a clear drawer would show the text under it); one `KEYMAP` table drives dispatch, help and footer hints. The `? ?` sheet is `<HelpSheet>` over `HELP_GROUPS`: a binding goes to its KEYMAP `group` (the AI keys, `m`), else to its first mode's `HELP_SECTIONS` entry, laid out by `helpLayout`. `m` (`minimap`, in `ZEN_OFF`, no footer hint) toggles `ui.minimap` (saved; toasts `minimap needs 110 columns` below `MINI_MIN_W`): `layout()` gives it the last `MINI_W` columns (`L.mini`; the measure shrinks only when it no longer fits left of it), `memo.mini` builds `miniInk` over `view.plain` (Source without its gutter), and a click jumps (`miniJump`). `#` (`headings`, global, in `WELCOME_OFF`, no footer hint, works in zen) cycles `ui.headings` through `HEADING_STYLES` (saved, toasts `headings · <name>`); it is passed to `render()` by `memo.doc`, `memo.peek` and `memo.themeSample` (`sampleView`), so it is part of their cache keys. `ui.motion` (the `motion` prop, else config `motion`; always off under `bun test` unless the prop says true) gates the animations: `timers.steam` (welcome ink-in, then steam every `STEAM_MS`; any key, a resize or a note opening stops it for good). With no note open the document area is `<Welcome>` (wordmark, bowl, steam, keycaps, recent projects from `memo.recents`; `↑↓` `⏎` and clicks act on the rows on screen; `?` opens the sheet at once). `layout()` gives it the whole width: no panel, drawer or minimap, a render-only override that leaves `sidebar` alone; the panel keys and `a`, `z`, `Z`, `s`, `w` (`WELCOME_OFF`) do nothing and the ghost line draws no hints there. The switcher gets a `peek` from `PEEK_MIN_W` columns: `memo.peekFile` reads the highlighted row's note (lines, `wordStats`, hash) and `memo.peek` renders only its `peekWindow` at the pane width, `peekLines` picks the rows, and the TL;DR shows only while fresh. A `hl` counter in the UI store is bumped when code highlighting lands so the memoized document re-renders. `a` (`summarize`, in `ZEN_OFF`) opens Info and cancels a running summary first (before the AI-off and empty-note checks), else starts one, only with an `ai` block (the footer hint too); `ui.ai`/`ui.summaries` hold config and cache, in-flight requests live in the `jobs` ref (max 3, one per path) redrawn by a 100 ms `timers.ai` throttle; regenerating shows nothing under `TL;DR · summarizing…` until the first token. Zen (`z`, settings popup `Z`) is a separate root keyed "zen"; it is runtime-only, and its settings persist under `zen`. `f` enters the `label` mode (`ui.labels`; not "hint", which is the footer key hints); labels drop when the view or scroll moves, and a missing heading leaves the note at its remembered position. The `f links` footer hint is `spare` (`fitHints` drops it first). Links resolve against `ui.linkTree`: the enclosing vault (`findVault`, nearest `.obsidian/`) when a single note was opened inside one, else the Files `tree`. The `stdin` prop makes the open path the relative `STDIN` (never a disk file; `read` serves the text): `stdinWorkspace` has an empty Files `tree` and a placeholder `linkTree` (`ui.linkLazy`; `ensureLinks()` scans the cwd once: a `setTimeout` after mount (`linkScanDelay`, 0; tests delay it) or the first `f`, link follow, Info link or `C-p`, whichever comes first), the panel has only Outline and Info for the whole piped session (`ui.piped`, set by `stdinWorkspace`, cleared by any `workspace()` rebuild, so also on a note followed from it: `panelViews()`, `stripLayout(SW, views)`; `1 2`, `3` does nothing, the view isn't saved), history keeps `STDIN` (no `existsSync` on it), the watcher skips it and `recordProject` the whole piped session, `e` toasts (hint hidden too), and `a` summarizes into the in-memory `ui.summaries` without `saveSummaries`. `e` (`edit`, in `ZEN_OFF`) suspends the renderer, runs `editorCommand` (`src/editor.ts`: `$VISUAL`/`$EDITOR`/`vi`, `+line` path or the editor's own syntax; `sourceLineAt` maps the top row to a source line — exact in Source, nearest heading plus rows in Preview) with `Bun.spawnSync` through `runEditor` (a piped session's editor reads keys from `/dev/tty`, none → toast), resumes and bumps `reload`; a non-zero exit toasts `<editor> exited with N` instead of `edited`; `edit(argv, piped)` prop stubs it in tests. `t` opens the theme picker (`ui.themePick`, a `ThemePick`; mode `theme`, typing goes to `pickQuery` as in the switcher, the `type filter` hint is spare): the app and the picker chrome stay in `themes[themeIdx]` while you move, `tab` / `S-tab` flip and `←` `→` set the mode, i.e. move the board's cursor across (on a single-mode family none does anything; `<ThemePicker>` gets `shown` = `pickShown` and `only` = `onlyMode`), `⏎` or a click on a row's name (`applyTheme`) sets `themeIdx` and saves `theme` (nothing listed: nothing happens), a click on a specimen (`onPick`) sets that family and mode and applies, `esc` or the backdrop drops the state. With `themeSplit(…).split`, `memo.themeSample` renders `SAMPLE` in the candidate at `peekW` (keyed on `hl`; the `hlSample` effect fetches its code highlights, which every theme then shares) and `<ThemePicker>` draws `memo.themePane` on the candidate's `background`; below `PEEK_MIN_W` only the board's cursor shows the mode. `C-p` opens the switcher (`ui.switcher`, mode `switch`) over `ui.linkTree`. `o` opens the Open picker (`ui.opener`, mode `open`); `ui.root` is the workspace, and every rebuild (start, `o`) goes through `workspace(root, note?)` — `switchWorkspace` also records the project, drops the vault index, re-arms the watcher and clears history. The index lives in the `vault` ref and is built on first use; `r` drops it and re-reads the `ai` block. Recents are the notes the document had focus with. Copy on select: OpenTUI's own mouse selection (any `<text>`, reverse video) fires the renderer's `selection` event on release; App trims it (`selectedText`, nav.ts) and sends it with `copyToClipboardOSC52`, toasting the count. AI jobs: the `jobs` ref is keyed `<kind>:<id>` (`tldr:<path>`, `gloss:<sectionId>`, `delta:<path>`, bare `ask`; `jobKey`), `MAX_JOBS` (3) counts every kind and the busy toast is `AI busy · 3 requests running`; each request re-reads `loadConfig().ai`. Zen gloss: `derive()` finds `gHere` (`glossTarget` for the reading section, `currentHeading`; only with an `ai` block or a gloss job still running, so `a` can cancel it) and the `sheet` (`ui.gloss` `{ id, key, heading, hash, fadeAt }` + `ui.glosses`, read once by `ensureGlosses` when zen meets an `ai` block; piped documents are never saved). `glossEntered` (an effect on `glossAt`, i.e. section changes only) fades the old sheet (`fadeGloss`, `timers.gloss`) and auto-shows a fresh cached or streaming gloss; outdated or missing ones need `a`. `zenGloss` (`a` in zen, spare footer hint only with an `ai` block) in order: cancel a running gloss for this section (before the AI-off check), `AI off`, `nothing to gloss here`, show a fresh cached gloss that is hidden, else (on screen, outdated or missing) `AI busy` / `resolveAI` toasts and `startGloss` (`glossRequest`, `chat`, cached on success; a failure closes the sheet and toasts, prefixed with the heading when the reading line has moved). `esc` in `clear` hides a non-fading sheet before leaving zen. The sheet (`glossRule`, `glossRows`, `GLOSS_ROWS` rows) is drawn over the bottom body rows. `D` (`explainChange`, global, in `ZEN_OFF`, footer hint `changes` while there are changes to explain): the `baseline` (open note's `noteText` + props key + time, memory only; taken in the `[openPath, reload]` effect, dropped by `dropDelta` on leaving or a failed read) is diffed with `diffSections` on each derive (`memo.diff`; null over `DIFF_LIMIT` or `DIFF_BUDGET` → `too large to compare`) into `ChangeView` for Info (`idle` list needs no AI; `loading` streams `parseDelta(…, partial)`; `result` only while the note still equals the explained text); `startDelta` sends `deltaMessage` with `chat` (a reply past `MAX_DELTA` keeps its finished part, `parseDelta(…, partial)`), then moves the baseline to the sent text; a second `D` cancels (checked before the AI-off test); `⏎` on a change row (`jumpChange`) goes to the section, or to `findQuote(view.plain, …, quoteNeedle(quote, source))`. Ask mode: a switcher query starting `?` (`questionOf`) swaps rows for `askRows`; `ui.switcher.ask` (`AskState`, dropped by any edit, `dropAsk` aborts) goes idle → `askStart` (tier 0, `chat` with `ASK_PROMPT`, question only; memo `askMemo` per question) → `result` (answers = `askCandidates` over the finished index, re-run on `ixVer`) → `askRerank` (tier 1, `rerankMessage`, memo `rerankMemo` per candidate ids + hash of the message that would be sent) → `reranked`; `answerTo` re-opens the note and re-checks the target with `askLocate` on the current `NoteDoc` (`heading gone` toast). One ask at a time, counted in `MAX_JOBS`; nothing is cached on disk.
- `src/overlay.tsx` — popup/picker components (`ThemePicker` with the `ThemeBoard` list (PickerList's paddings; a `boardHeader` row, then per family the name with its hits and a `boardSlot` box per mode, so a click knows its mode — a missing mode's slot swallows the click; the cursor row is tinted `backgroundElement`, not primary), the `modeSwitch` in `PickerInput`'s `right` slot (the missing side of a single-mode family muted and struck through, clicks ignored) and a pane on the candidate's background; find list, `Switcher` with its optional peek pane split by `switchSplit`), `HelpSheet` (wordmark, chips, two columns from 100) and `Welcome` (the empty-state page). Rows move the highlight on `over` only when `usePointer().moved` says the pointer left its last cell (see Gotchas); App's two roots and the popup box record it with `note`.
- `src/ai.ts` — every AI request and the only network I/O. `PRESETS`/`Provider`, `PROMPTS` (`{ tldr, gloss, delta, ask, rerank }` versions; bump one with its prompt; `PROMPT_V = PROMPTS.tldr`), `normalizeAI`/`resolveAI` (target + key from env only; no plain `http:` off localhost for the key or any custom `headers`; optional `gloss` field via `parseGlossStyle`/`GlossStyle` = `explain | simplify | translate:<tag>`, dropped alone when invalid; the endpoint is the baseURL's path + `/chat/completions`, its query kept, a fragment dropped), `noteText`/`clip`/`buildRequest(t, system, user)` (OpenAI-compatible chat, streaming, `redirect: "manual"` (a 3xx fails as `redirect` → `<host> redirects · set baseURL to the final URL`; the request is never re-sent), no `max_tokens`/`temperature`), `sseParser`, `jsonReply`, `cleanSummary` (cap `MAX_SUMMARY`), `stripThink` (the `clean` of the structured requests: ask, rerank, `D`; the raw reply is capped at 64k), `extractJSON` (drops `<think>`, one code fence, slices the outer `{}`/`[]`; `undefined` on failure; no `response_format`), `tokens`/`fmtTokens` (code points / 4 → `~1.3k tokens`), `shortModel`, `errMessage`/`aiError` (toast strings with `ErrCtx.noun` summary/gloss/explanation/answer: `<noun> cut short`, `empty <noun>`…; new failure `invalid` → `no usable <noun>`; the key and custom header values are redacted in `chat`; 401/403 without a key → `unauthorized · set keyEnv`), `chat(t, { system, user, maxOut, clean }, opts)` (idle/total timeouts, abort, never throws, returns `text` cleaned and `raw`; `fetch` injectable, App takes a `fetch` prop) with `summarize` its TL;DR wrapper.
- `src/summaries.ts` — the cache store, `$XDG_CACHE_HOME/brothy/<name>.json` (relative ignored → `~/.cache/brothy/`; dir 0700, file 0600): generic `loadCache`/`saveCache` (merge-on-save, newest `at` wins, pruned to a cap), `summaries.json` (`loadSummaries`/`saveSummaries`, `CACHE_CAP` 500) and `glosses.json` (`loadGlosses`/`saveGlosses`, key `<sectionId>#<style>`, `GLOSS_CAP` 2000); `textHash`/`isFresh(e, hash, v = PROMPT_V)` (hash + prompt version). Split from `ai.ts` to avoid an `ai.ts ↔ config.ts` cycle. Ask and reload explanations have no cache.
- `src/panel.ts` — pure data for the panel: Outline and Info rows (`tldrItems`/`SummaryView`: the TL;DR block, states none/streaming/fresh/outdated), links. the Changed block of Info (`ChangeView`, `changeItems`, `MAX_CHANGE_ROWS`; rows are `change` items, `stop` unless removed), `noteIndex` (cached per tree), `resolveLink`, `linkDest` and `findHeading`/`headingKey` decide where a link goes.
- `src/status.ts` — status strings (`LOGO`; `WORDMARK`/`fitWordmark` — the "brothy" wordmark in the empty state, help popup, README and `--version`; top line: `headerLayout`, `shrinkFolder`, `logoState`, `mainHeadingVisible`, `locationParts`; state cluster, progress label, hint fitting) and toasts.
- `src/nav.ts` — pure helpers for scrolling, search, scrollbar thumb and strip layout (`stripLayout`: a superscript key number before each tab label, `¹Files`; two-cell gaps below `STRIP_COMPACT_BELOW` panel columns), match index, `findQuote` (row where a phrase starts in a section's plain rows, wrapped phrases and case folded) and the `cached` single-entry memo (unit-tested without a renderer). Also link labels (`visibleLinks`, `linkLabels`, `narrowLabels`, `overlayAt`) for the `f` mode, drawn over rows at render time.
- `src/zen.ts` — Zen mode's pure side: `ZenConfig` (`measure` is a number or `"full"`; `stepMeasure` is the dial) + `normalizeZen`/`pickZen` (field-wise validation used by `config.ts`), settings-popup rows (`zenRows`, `zenAdjust`), `sectionRanges`/`sectionAt`, `typewriterTop`, `pageSlice`, `headingPath`, `dimSpans` (Spotlight), `wordSuffix`/`minutesLeft`, `prompterRate`, `fadeStep(elapsed, hold)` with `HINT_HOLD` (hint/ghost fade).
- `src/vault.ts` — the `C-p` switcher's pure side: the lazy index (`NoteDoc` per note: aliases, Source-outline headings, searchable text — heading lines blank, inline marks stripped by `plainLine`, so text hits never repeat Headings and context matches its highlights — with `foldSame` offsets; `refreshIndex` re-reads changed mtimes in `CHUNK`s and stops when `live()` is false) and the search (`searchVault`: Notes / Headings / Text with `SWITCH_CAP`; `recentSection`; row helpers `switchRows`/`stepRow`/`nextSection`; exports `headingAt`/`lineOf`; `SwitchRow` also has `answer` (a section the ask found: heading key + `ord` + the query that matched), `askAction` (`⏎ ask` / `↻ rerank with excerpts`) and `askNote` rows). A heading hit's index is `view.headings[i]` by outline parity.
- `src/sections.ts` — pure, over `sourceScan`: `noteSections` (per heading: depth, `key`, `ord` among equal keys, `own`/`tree` source-line ranges, one pass with a depth stack; index -1 is the lead-in), `sectionSource(src, i, "own" | "tree", secs?)` (front matter, comments and the heading removed; pass `secs` to skip re-scanning — `glossTarget` scans once per text), `sectionOf(headings, line)` (derive()'s `currentHeading` rule), `sectionId(path, s)` = `path#key#ord`, stable across edits elsewhere. By outline parity `index` is the same heading in Preview, Source and the vault index.
- `src/gloss.ts` — zen gloss, pure: `glossTarget` (own text, subtree under `GLOSS_MIN_WORDS`), `glossSystem`/`glossRequest` per style (`PROMPTS.gloss`), `glossKey`, `glossRule`/`glossRows` (sheet rule and at most `GLOSS_ROWS` rows).

- `src/ask.ts` — ask → jump, pure: `questionOf`, prompts (`ASK_PROMPT`, `RERANK_PROMPT`), `parseQueries`/`parseRerank` (the model proposes terms or orders ids it was sent; unknown ids dropped), `askCandidates` (local ranking over the vault index: heading 3, text 1, name 1, top `MAX_CANDIDATES`), `askLocate` (finds the section again in the note as it is now), `rerankMessage`/`rerankCost` (tier 1 text and its token estimate), `askRows`/`askSection`/`askTitleNote` (switcher rows per state), `putNewest` memo helper.
- `src/projects.ts` — recent projects (`projects.json` next to `config.json`, `ProjectEntry`: root, lastNote, Preview top, at; cap 20) and the `o` picker's pure side: `remember`, `rankProjects`, `pathCompletions` (injectable `DirIO`), `openRows`, `tildify`/`expandTilde`.
- `src/history.ts` — `H`/`L` back/forward, pure: `visit` (cuts forward, no consecutive duplicates, cap 100; a `peek` entry — a Files preview — is replaced by the next visit until `keep` marks it focused or followed from), `stepTo`/`go`/`drop`. App holds it in `ui.history`; every open goes through `openFile(path, how)`, and an entry stores the scroll entry (`Spot`: key, top, geo) the note was left at.
- `src/stdin.ts` — `MAX_BYTES` (5 MB, notes and piped documents) and `readCapped(stream, max)`: the piped document as UTF-8, or null as soon as it passes the cap (the rest is never read).
- `src/editor.ts` — `e`: `editorCommand(env, path, line)` (`$VISUAL`, else `$EDITOR`, else `vi`, split on spaces, never a shell, then the line in the command's syntax by basename: `-g path:line` for `code`/`codium`/`cursor`, `path:line` for `subl`, else `+line` and the path) `sourceLineAt` (the source line for the top row: exact in Source, nearest heading plus rows in Preview) and `runEditor(argv, piped, io)` (`EditorIO`: suspend, spawn, resume; a piped session opens `/dev/tty` for the editor's stdin and closes it after; `EditResult` is the exit or why it never ran).
- `src/watch.ts` — `watchPath`: live reload that survives atomic saves (watches the parent dir) and falls back to polling with a synchronous baseline.
- `src/markdown.ts` — core design: `marked` lexer output is converted to **pre-wrapped, styled lines** (`Span[]` per `Line`) at a given width. Scrolling, heading jumps (`Rendered.headings` holds line numbers), and search all operate on exact line indexes, so any change to rendering must keep that line↔heading mapping consistent. `render(…, { headings })` takes a `HeadingStyle` (`HEADING_STYLES`: `classic` default; `bars`/`ladder` a level-colored prefix with continuation rows indented, no H1 rule row; `rules` fills H1/H2 to the measure on the last row only, wrapping at `max − 2` to leave room, `╌╌` for H3, bare bold for H4–H6); `Rendered.headings[i].line` is always the first row, Source ignores it. Also holds `wrap` (grapheme-aware, `preserve` mode for code), `parseFrontMatter`, `stats` (`wordStats`: its words and minutes without lexing), and `renderSource` (its outline mirrors the preview's headings; `Rendered.srcRow` maps each source line to its first row). `sourceScan` gives the Source outline (with source lines) and the searchable lines without laying out (the switcher's index). Input is normalised first (BOM, CRLF, control characters). Tables never exceed the width: columns shrink, narrow ones truncate with `…`, columns that cannot fit become a final `…` column. Widths use `Bun.stringWidth`. Obsidian: one shared `Marked` instance (`md`, with `lexBlocks`/`lexInline`) carries the `==highlight==` extension — never lex with `new Lexer` or `Lexer.lexInline`. `%%comments%%` are cut before lexing (`stripComments`); `scanComments` gives Source the same hidden lines so both outlines stay equal. Callouts (`CALLOUT_KINDS`, `calloutOf`) render through `blocks()` so body headings keep their lines; `dataview`/`dataviewjs`/`tasks` fences are one row; HTML goes through the `HTML_TAGS` whitelist (`stripTags`). Wikilinks are a second extension on `md` (`wikilinkExt`, `parseWikilink`, `wikiLabel`); every link token gets an id that rides on its spans as `Span.link` into `Rendered.links` (`same()` compares it so links never merge). `render(…, { exists })` mutes unresolved targets.
- `src/highlight.ts` — code-block colors. JS/TS/JSX/TSX/Zig go through OpenTUI's tree-sitter worker (async); everything else uses a small per-language-family fallback (comments/strings/numbers). `render()` only reads the cache (`codeSpans`) and records misses in `Rendered.pending`; callers `await ensureHighlights(pendingHighlights(r))` and re-render. The cache stores semantic kinds, colored from the `Theme` at render time. A highlighted block must have exactly as many lines as a plain one. The parser worker keeps the process alive: call `shutdownHighlighter()` in scripts/tests (the app exits via `process.exit`).
- `src/spans.ts` — `Span` and the attribute flags `A` (re-exported by `markdown.ts`; exists to avoid an import cycle with `highlight.ts`), plus `safe`/`safeLine`: control characters (C0, DEL, C1) become U+FFFD so nothing reaches the terminal as an escape sequence. Applied at the sources (`normalize`, front-matter values, `FileNode.name`/`rel` — `path` stays raw for I/O — and decoded link targets) and again in `flash()` and the `Row`/`Line` span renderers. `safeLine` also turns tab/newline into spaces for one-row text.
- `src/glyphs.ts` — `superscript` (tab key numbers).

## Gotchas

- OpenTUI's React reconciler does not clear style props that disappear between renders. Conditional branches rendering different boxes in the same spot need distinct `key`s (see the `key="empty"`/`"error"`/`"lines"` and `"side-inline"`/`"side-drawer"` boxes in `App.tsx`).
- After a render whose hit grid changed, OpenTUI hit-tests the resting pointer again (`recheckHoverState`) and sends `over` to whatever is under it now — a row re-keyed as the highlight moves (`sel`/`row` keys), or scrolled under it — at the last event's cell. A hover handler that acts on every `over` undoes keyboard and wheel moves; guard it with `usePointer().moved` (overlay.tsx). A real move sends `out`, then `over`, already at the new cell, so `note` records only the pointer's own events (move, drag, down, up, scroll), from catch-all `onMouse` boxes above the rows; a handler below them that stops propagation calls `note` itself.
- `marked` 18 gives raw text for code spans and pre-decoded numeric entities in text; `markdown.ts` decodes only named entities (single pass). marked's lexer also hangs on tables with ~150k+ rows.
- OpenTUI's tree-sitter worker ignores `#match?` predicates, so every identifier arrives as variable+type+constant; `tokenize` in `highlight.ts` re-checks `type`/`constant` against the text. `preloadParser` is unreliable for aliases; use the static `PARSER_FILETYPES` list (a test checks it against the library).
- Zen keeps the per-file scroll `top` as the only position: in Typewriter it *is* the reading line, in Pages it is the page anchor (its section is the page), and in both `maxTop` is the last line. Display goes through `derive().win` (`first`, `lo`, `hi`) — never slice `view.lines` from `top` directly in zen.
- Outline parity: anything Preview hides (comments, collapsed fences) must also be skipped by `sourceStructure`; `tests/markdown-obsidian.test.ts` checks `render` vs `renderSource` outlines.
- Tests: `markdown*`, `files`, `config`, `args`, `nav`, `panel`, `status`, `watch`, `theme`, `highlight`, `zen`, `vault`, `history` and `projects` are unit tests; `overlay.test.tsx` mounts the popup components through `testRender`; `cli.test.ts` spawns the CLI (non-TTY paths); `ai`, `summaries`, `sections`, `gloss`, `delta`, `ask`, `glyphs`, `chrome`, `help`, `welcome`, `minimap`, `peek`, `themepick` and `stdin` are unit tests too, and `cinema` covers the pure side of `scripts/cinema.ts`; `app.test.tsx` also points `XDG_CACHE_HOME` at a temp dir and AI tests pass a stub `fetch` to `mount`; it mounts `<App>` through `testRender` with `XDG_CONFIG_HOME` pointed at a temp dir (sidebar and theme persist, so the config is cleared after each test) and shuts the highlighter worker down at the end. UI changes are also worth a look through the snapshot script.
